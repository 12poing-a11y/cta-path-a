# R8 长样本数据覆盖报告（步骤 5，运行前；只读侦察，没有跑任何策略）

窗口 2016-01-01 → 2025-12-31。数字全部来自 `.cache/history/*0.json`、`.cache/contracts`、`.cache/member`、`universe.json`、`research_cost.json` 的只读检查，脚本：`_probe_hist.py` `_probe_data2.py` `_probe_settle.py` `_c_pool_static.py` `_render_coverage.py`。**在磊确认之前，不开发长样本入口，不跑任何长窗口组。**

## 0. 先说三个会改变“长样本在检验什么”的发现

1. **`historical_backtest.py` 目前没有长样本入口**（没有 `--start/--end/--history-source`，也没有 `lab/research/long/`）。要跑长窗口，需要先实现入口（预注册 §9 之后、磊确认之后才做）。
2. **本地没有 2016–2024 的合约级数据**：`.cache/contracts` 共 615 个合约文件，最早的逐合约 bar 是 2024-09（AU）/ 2024-10（其余），交割月从 2025-10 起。所以 R6c 的换月复权（`main_map`）、合约成交、交割月拦截在长窗口里都做不了，只能用主力连续序列（有换月跳空）+ 连续序列代理成交。
3. **席位数据只有郑商所、上期所，从 2018-01-02 起**（`.cache/member`：czce 2157 个文件、shfe 2157 个文件，起 20180102；大商所 `_dce_dl` 为空）；升贴水缓存（`.cache/akshare/basis`）只覆盖 2025-10 以后。所以 **A 的 seats 入场过滤、carry 旁路在长窗口里无法复现**，长样本只能用“基础模式”。R-track 文档（R8 一节）本来也写了这一点。

**含义**：长窗口检验的是 **A 的核心（信号 + 仓位 + 名义帽 + 持仓数 + 板块上限 + 成本）**，不是冻结的完整 A（seats + carry + R6c）。预注册 §9 写了这一点。完整 A 只能靠前向 shadow 检验。另外，没有换月复权时，换月跳空会产生假止损 / 假信号（R6 阶段修的就是这一类问题），长窗口的结果会带这个偏差。

## 4. 数据缺口处理（建议，待确认）

1. **不插补，品种数据不齐就不纳入**：某品种在某交易日没有 bar → 当天该品种不可交易（不产生信号、不入场；已持仓的盯市沿用引擎现有行为，实现时要核对并写单元测试）。
2. **上月末缺 `settle`**：该品种当月不入 C 的池（不用收盘价代替）。大商所 8 个老品种各少 9 个月（2017-12~2018-03、2020-03~2020-07），EG、EB 各少 5 个月（2020-03~2020-07），上期所系 2019-05 少 1 个月，见 §3.1。
3. **成交量为 0 的 bar**（FU 2016~2018-06）视为无有效行情日。
4. **晚上市的 5 个品种**：EB、EG、SA、SP、SS 从各自预热期结束日起纳入（§1.1）。
5. **合约乘数 / 手续费 / tick**：用当前值套用全部年份，作为已知偏差披露。
6. **长样本数据模式**：基础模式（无席位、无升贴水、无合约级复权、连续序列代理成交）。**这是必须由磊确认的一项**：它让长窗口回答的是"A 的核心"，不是"冻结的完整 A"。

## 5. 需要磊确认的事项
