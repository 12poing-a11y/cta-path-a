**要点**

- **所有 27 个品种里，卡住开仓的都是名义（②），不是风险（①）**：中位日里每个品种按名义算出的最低本金都高于按风险算出的。
  例：AU 按风险只要约 75.9 万，按"名义≤帽一半"要 384 万；CU 30.3 万 vs 208.6 万；AG 45.5 万 vs 99.4 万。
- **BASE（20 万）下**：AG、AL、AU、CU、NI、RU 六个品种**每一天**1 手名义就大于整个名义帽（10 万），JM（1.4% 的天）和 P（9.7% 的天）偶尔也是；
  另有 CF、I、JM、P、SR、SS 每天 1 手名义 > 帽的一半。BASE 的 27 个品种里，在"①且②"下 100% 的天都可开的只有 9 个（200k 列：FG、SA、V、MA、TA、M、RB、JD、L）。
- **实际本金 100 万下**：**AU、CU 开不出来**（AU 每天 1 手 ≈ 本金的 96%，> 帽 50%；CU 88% 的天 1 手 > 整个帽，其余天也 > 帽一半）；
  **AG 一开就占满帽**：中位 1 手 = 本金 24.8%，约一半的天（49.5%）超过帽的一半，最大 1 手名义 = 本金 46.3%（≈ 帽的 93%）；AG 最大 1 手止损风险 = 本金的 3.48%，高于 2% 预算，那些天 `floor` 后是 0 手。
  其余 24 个品种在 100 万下 1 手 ≤ 帽的一半。
- 因此对 F1（名义半条）可以预期：100 万下它基本只会碰到 AG / CU / AU。这是静态预期，不是结果。

## (b) "单手可承受性前半条"是否已被 floor 取整挡掉；R4b 补手能否把 0 手补回 1 手

"前半条" = F1 定义里的"1 手止损风险 > 单笔风险预算 → 不入场"。

- 引擎 `sizing()`：`lots = floor(day_risk / risk_per_lot)`，之后只会再乘 carry 乘数（≤1）并 floor。所以 **`lots ≥ 1` ⇔ `risk_per_lot ≤ day_risk`**，这是恒等式，不是巧合。
- 实测（BASE，全年 216 天）：算出 ≥1 手的候选日 **980** 个，其中 `risk_per_lot > day_risk` 的 **0 个**；算出 0 手的候选日 **125** 个，其中 `risk_per_lot ≤ day_risk`（即不是因为风险买不起）的 **0 个**（carry 乘数造成的 0 手也未出现）。
- **结论：前半条在 `min_lots=0` 下是多余的，已被 floor 完全挡掉。** 按你的规定，F1 只保留名义那半条（1 手名义 > 当时名义帽额度的 50% → 不入场）。
  （`min_lots>0` 才会让前半条有意义，本轮 `min_lots` 不变，为 0。）
- **R4b 补手**：`topup` 只处理"请求手数 > 0、被统一缩放 + floor 压到 0 或不足"的候选；`sizing` 算出 0 手的信号状态是 `lots0`，引擎在 `_st != "ok"` 处 `continue`，**根本不进入候选列表**，补手够不着。
  实测：125 个 0 手信号日里被最终选中的 **0 个**。R4b 在全年确实补了 113 手、救回 28 个"被名义帽缩到 0"的候选（`caps_topup_lots=113`、`caps_topup_revived=28`），但这些都是"请求手数 > 0"的候选，不是 0 手信号。
  **所以 R4b 不会把 0 手补回 1 手。**

## (c) 对照组（BASE）跳过的信号数拆分

单位：**信号日**（同一个信号连续几天，每天算一次；与上一轮报告的 125 同口径）。每个候选日只归入下表一类，按引擎流水线顺序判定：
`sizing 算出 0 手` → 帽内动量 → 板块 → N 帽 → 名义缩放 → ATR 风险缩放 → 硬裁剪/回填 → R4b 补手。归类逻辑在脚本里复刻了板块和 N 帽两步，并与引擎自己 `meta["bucket_skipped"]` 逐日断言相等。

| 类别 | 信号日数 | 主要品种 |
|---|---|---|
| 算出 0 手（风险预算买不起 1 手） | 125 | AG 58, AU 31, CU 20, NI 14, RU 2 |
| 名义帽缩到 0（总帽−已持仓后的额度，统一缩放后 floor 为 0，且未被 R4b 补回） | 178 | JM 35, NI 22, I 22, AL 21, CF 20, P 20 |
| 持仓数已满（当日候选多于空位，被 N 帽挡掉） | 31 | I 6, SS 6, TA 4, CF 3, P 2, FG 2 |
| 板块已满（同板块已有持仓或同日更强者占位） | 626 | BU 76, PP 74, FG 72, L 58, TA 50, EG 50 |

- **对账**：算出 ≥1 手的候选日 980 = 被选中 145 + 名义帽缩到 0 的 178 + 持仓数已满 31 + 板块已满 626（帽内动量、ATR 风险缩 0、硬裁剪三类均为 0）。
  另有算出 0 手的 125 个信号日在候选列表之外，所以"跳过的信号日"合计 = 125 + 178 + 31 + 626 = 960。
  被选中的 145 个入场请求最终成交 57 笔，差额发生在选中之后的入场环节（价格/可交易性/交割等引擎侧过滤），本步不展开。
- **"持仓数已满"在 BASE 上几乎不是约束**：216 个交易日**没有一天**开盘时持仓已满（日初空位 1/2/3 个的天数分别为 28/83/105；日末持仓 0/1/2 笔分别 70/96/50 天，从未到过 3 笔）。
  上表 31 个"持仓数已满"是当日候选数多于当日空位被 N 帽挡掉的，不是"满仓日"。引擎在满仓日不评估信号，但本样本里没有满仓日，所以这一类没有信息缺口。
- **真正卡住成交的是名义帽**：名义帽缩到 0（178 信号日）+ 算出 0 手里的大面值品种（AG/AU/CU/NI，123 个信号日）。
  "板块已满" 626 个信号日大部分是同板块内竞争（同一天同板块只能取最强的一个），不等于"容量不足"，读的时候不要和前两类等同。
- 这一步只是描述性诊断，不含任何收益结论。
